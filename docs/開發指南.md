# 開發指南

本文件整理 MyDraw 的開發環境、建置、測試、版本與發行流程。完整團隊規範以根目錄 [`AGENTS.md`](../AGENTS.md) 為準；本文件提供給新加入開發者的快速入口。

## 1. 開發環境

| 項目 | 需求 |
| --- | --- |
| 作業系統 | Windows 10 1809（17763）以上 |
| .NET SDK | .NET 10 SDK（本專案以 10.0.403 驗證） |
| IDE | Visual Studio 2026（可選）或任何支援 C# 的編輯器 |
| 架構 | x64 開發機可建置 x64 與 arm64 |
| 套件 | 由 `Directory.Packages.props` 集中管理 |

第一次取得原始碼：

```powershell
git clone https://github.com/mark216tw/win-mydraw-01.git
cd win-mydraw-01
dotnet restore MyDraw.sln
```

## 2. 常用指令

```powershell
# 建置（開發迭代）
dotnet build MyDraw.sln -c Debug -p:Platform=x64

# 單元測試
dotnet test MyDraw.sln -c Debug -p:Platform=x64

# 格式檢查
dotnet format MyDraw.sln --verify-no-changes --no-restore

# 執行
dotnet run --project src\MyDraw\MyDraw.csproj -c Debug -p:Platform=x64
```

開發與測試一律使用 `Debug`。`Release` 僅在明確發行時使用。

## 3. 測試分級

依 `AGENTS.md` 的風險分級：

### Tier 1（每次編譯或 XAML 變更）

```powershell
dotnet build MyDraw.sln -c Debug -p:Platform=x64
```

### Tier 2（功能完成）

```powershell
dotnet format MyDraw.sln --verify-no-changes --no-restore
dotnet test MyDraw.sln -c Debug -p:Platform=x64
```

依變更範圍加跑：

| 變更類型 | 驗證腳本 |
| --- | --- |
| 筆刷／渲染／輸入 | `tools\Verify-BrushEffects.ps1` |
| 專案存讀／檔案選擇器 | `tools\Verify-OpenExport.ps1` |
| 設定／圖層／工具列／AutomationId | `tools\Verify-UiSmoke.ps1` |

### Tier 3（版本更新或發行前）

```powershell
.\tools\Verify-UiSmoke.ps1 -ExecutablePath .\src\MyDraw\bin\x64\Debug\net10.0-windows10.0.19041.0\win-x64\MyDraw.exe
```

渲染或筆刷變更時，再補手動視覺確認。

> 驗證腳本會啟動實際程式並操作 UI。若本機有殘留的復原快照，啟動時可能跳出復原對話框，導致 UI Automation 失敗。測試前可暫時移開 `%LOCALAPPDATA%\MyDraw\Recovery\`，測試後再還原。

## 4. 專案慣例

- 4 空格縮排；`PascalCase` 類別／方法；`camelCase` 參數／區域變數；私有欄位 `_camelCase`。
- 使用 file-scoped namespace、nullable、隱式 using。
- 非同步方法以 `Async` 結尾；函式庫層使用 `ConfigureAwait(false)`，UI 層不加。
- 一個檔案一個公開型別，檔名與型別同名。
- 使用者可見文字放 `.resw`，不要寫死在 XAML／程式碼。
- 不要新增未在 `Directory.Packages.props` 宣告的依賴。
- 不要關閉警告；`TreatWarningsAsErrors` 開啟。
- 不要在 UI 執行緒做長時間 I/O。
- 不要留 `TODO` 當完成功能、測試假資料或 `Console.WriteLine`／`Debug.WriteLine`。

## 6. 版本規則

- 版本定義在 `Directory.Build.props`：
  - `Version`：`主.次.修`
  - `AssemblyVersion`：主／次版變更時才調整
  - `FileVersion`：可隨每次發行調整
- 功能變更需遞增版本。
- 發行時同步更新：
  - `CHANGELOG.md`
  - `RELEASE_NOTES.md`
  - `docs/DEV_LOG.md`
  - 需要時更新本文件與其他 docs

## 7. 發行流程

### 7.1 發行前檢查

1. 確認 `Directory.Build.props` 版本正確。
2. 更新 `CHANGELOG.md`、`RELEASE_NOTES.md`、`docs/DEV_LOG.md`。
3. 執行 Tier 2 與 Tier 3 驗證。
4. 確認 `git status` 沒有不該提交的檔案（`bin/`、`obj/`、`publish/`、`artifacts/` 已被忽略）。

### 7.2 建置 non-self-contained 發行檔

```powershell
# x64
dotnet publish src\MyDraw\MyDraw.csproj -c Release -p:Platform=x64 -r win-x64 `
  --self-contained false -p:WindowsAppSDKSelfContained=false `
  -p:WindowsPackageType=None -o publish\win-x64

# arm64
dotnet publish src\MyDraw\MyDraw.csproj -c Release -p:Platform=arm64 -r win-arm64 `
  --self-contained false -p:WindowsAppSDKSelfContained=false `
  -p:WindowsPackageType=None -o publish\win-arm64
```

### 7.3 打包

```powershell
Compress-Archive -Path publish\win-x64\* -DestinationPath publish\MyDraw-0.14.2-win-x64.zip -Force
Compress-Archive -Path publish\win-arm64\* -DestinationPath publish\MyDraw-0.14.2-win-arm64.zip -Force
```

發行 zip 建議一併包含：

- `LICENSE`
- `README.md`（可選，方便離線閱讀）

### 7.4 建立 GitHub Release

```powershell
git tag v0.14.2
git push origin main
git push origin v0.14.2
gh release create v0.14.2 `
  publish\MyDraw-0.14.2-win-x64.zip `
  publish\MyDraw-0.14.2-win-arm64.zip `
  --title "MyDraw 0.14.2" `
  --notes-file RELEASE_NOTES.md
```

> `gh` 需先登入 `mark216tw` 帳號，且具備 `repo` 權限。

### 7.5 版本標籤規則

- 標籤格式：`v<版本>`（例如 `v0.14.2`）。
- 標籤建立後不要任意移動；若發行內容有誤，應建立新版本。

## 8. 除錯

| 問題 | 檢查位置 |
| --- | --- |
| 啟動失敗 | `%LOCALAPPDATA%\MyDraw\logs\crash-YYYYMMDD.log` |
| 設定異常 | `%LOCALAPPDATA%\MyDraw\settings.json`、`.corrupt` |
| 復原流程 | `%LOCALAPPDATA%\MyDraw\Recovery\` |
| 專案載入錯誤 | `ProjectFileException` 的資源 key 與 `document.json` |
| UI Automation 失敗 | 是否有殘留復原對話框、視窗是否在前景 |
| 渲染接縫／殘影 | `LayerRenderCache` dirty 圖塊範圍與筆刷透明度 |

## 9. 不要提交的內容

`.gitignore` 已排除：

- `bin/`、`obj/`、`publish/`、`artifacts/`
- `.vs/`、`.vscode/`、`*.user`
- 測試結果與 coverage
- NuGet 套件與暫存
- `.pfx`、`.p12`、`.snk`、`.key`、`secrets.json` 等機密
- MSIX／APPX 產物

不要將 API Key、密碼、權杖或個人憑證寫入原始碼或版本控制。

## 10. 文件維護

- 功能或架構變更時，同步更新 `docs/` 下的對應文件。
- `docs/DEV_LOG.md` 於開發當下更新，不要事後補寫。
- 文件一律使用繁體中文；程式碼與識別字維持英文。
- 指令、路徑與版本號需與實際專案一致。
